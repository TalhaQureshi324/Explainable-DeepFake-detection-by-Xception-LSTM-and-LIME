# Hugging Face Space Integration — Update Instructions

Phase 5-HF: the Vercel frontend calls our existing Space for real inference.
No FastAPI hosting, no Docker, no local `.keras` files on Vercel.

## Architecture

```
Browser (Vercel site)
  │
  ├─ upload media ──────────────────▶ Hugging Face Space (Gradio)
  │     @gradio/client                /predict_deepfake (basic)
  │     or /analyze_structured        /analyze_structured (structured + PDF)
  │
  └─ results/report/PDF ◀──────────── (face/LIME/PDF artifact URLs)
```

## Update the Space (one-time, ~5 minutes)

The extended Space app adds `/analyze_structured` + PDF generation **without
breaking** the existing `/predict_deepfake` endpoint or the Gradio UI.

1. Clone the Space repository:
```bash
git clone https://huggingface.co/spaces/MuhammadTalha121/Deep-Fake-Detection hf_space_deploy
cd hf_space_deploy
```

2. Copy the extended files from this repository (`hf_space/` folder):
```bash
# from the FYP repo root
cp hf_space/app.py hf_space_deploy/app.py
cp hf_space/report_pdf.py hf_space_deploy/report_pdf.py
cp hf_space/requirements.txt hf_space_deploy/requirements.txt
```

3. Commit and push:
```bash
cd hf_space_deploy
git add app.py report_pdf.py requirements.txt
git commit -m "Add structured analysis endpoint + ReportLab PDF (Phase 5-HF)"
git push
```

The Space will rebuild automatically (~3-5 minutes). **Rollback:** `git revert HEAD && git push` restores the previous version.

## Deploy the frontend to Vercel

1. Import the repository into Vercel (Services beta enabled).
2. Set project environment variables:
   - `NEXT_PUBLIC_HF_SPACE_ID=MuhammadTalha121/Deep-Fake-Detection`
   - `NEXT_PUBLIC_INFERENCE_MODE=huggingface` (or omit — this is the default)
3. Deploy. The frontend serves at the project domain; the browser talks
   directly to the Space for inference.

## What works without Supabase

- ✅ Upload image or video → real prediction from the Space
- ✅ View results (verdict, score, threshold, processed face, LIME)
- ✅ Interactive report with limitations and uncalibrated-score disclaimers
- ✅ PDF download (generated by the Space from the structured result)
- ✅ English/Urdu + RTL, dark/light themes, responsive
- ⏸ Auth + persistent history + dashboard — requires Supabase (Phase 4E+)

## Model replacement (Phase G)

When a retrained V3 checkpoint is ready:
1. Upload the new `.keras` file to the Space
2. Update `MODEL_PATH` in `app.py` (and add a fallback if desired)
3. The structured endpoint automatically reports the new model's version,
   SHA-256, input frame count and threshold — the frontend picks these up
   without any changes.
